# CR-0002: Resolve four spec inconsistencies found by property testing

- **Status:** Approved
- **Approval:** Approved by user
- **Spec:** `fb-ai`
- **Affected tasks:** `5.1`, `9.1`, `9.4`, `5.2`–`5.4`
- **Requirements:** 3.5, 6.5

## Reason

Implementing Correctness Properties 1–33 as `fast-check` tests surfaced four
places where the requirements, the design, and the implementation do not agree.
Three are documentation defects; one changes runtime behavior. None were
detectable by the earlier example-based tests.

### 1. The 20% copyright measure does not measure verbatim copying

Requirement 6.5 concerns `sao chép nguyên văn` — verbatim copying — and offers
two thresholds: 50 consecutive words, or 20% of the draft's total words.

`compareCopyright` implements the second threshold by collecting the source
capture's tokens into a set and marking every draft position whose token appears
in that set. Word order and adjacency are irrelevant, so the measure counts
incidental vocabulary overlap rather than copied passages.

The practical consequence is a false positive that is likely rather than
theoretical for this product. A Vietnamese draft that shares only common
function words with a captured source — `và`, `của`, `là`, `cho`, `một`,
`được` — can reach 20% matched positions with no copying at all, and is then
flagged as a copyright risk. There is no stop-word list and no minimum-run
threshold to prevent it.

Property 23 currently encodes the existing behavior because `design.md` states
it explicitly ("compares contiguous normalized token runs **and** total matched
draft tokens"). The behavior is faithful to the design; the design is wrong
about what Requirement 6.5 asks for.

### 2. Requirement 6.5 says "exceeds" while the implementation uses "at least"

Requirement 6.5 says `vượt quá giới hạn` (exceeds the limit), which literally
means more than 50 consecutive words and more than 20%. `tasks.md` task 9.1 and
the implementation both use `>=`, so exactly 50 consecutive copied words is
flagged. The documents contradict each other on the boundary.

### 3. Property numbering diverges between the design and the tasks

`design.md` numbers 16 aggregate behavioral invariants. `tasks.md` numbers 33
finer-grained test-level properties. Both are legitimate decompositions, but
`Property 14` means "Concurrent mutations are serialized" in the design and
"Generated drafts satisfy the multi-format structure" in the tasks. Test tags
follow the `tasks.md` numbering, so a reader starting from the design is
misdirected.

### 4. Research-time permission refusals are invisible

`ResearchAggregator` skips a related source whose terms or robots.txt prohibit
access, but records nothing. `unreachableSources` holds only sources that failed
or timed out. Requirement 3.5 covers unreachable sources, and Requirement 1.6
covers collection-time permission refusals, so a research-time refusal falls
between them and the Operator cannot see that a source was deliberately
excluded.

## Requested change

### Change 1: the ratio threshold counts only copied passages

Add `minRunTokens` to `CopyrightLimits`, default **5**, and count a draft token
toward `matchedDraftRatio` only when it belongs to a contiguous matched run of at
least `minRunTokens` tokens. Leave the 50-consecutive-word rule unchanged.
Record `minRunTokens` and the qualifying run lengths in `CopyrightComparison` so
the decision stays reproducible and explainable.

Rationale for 5: long enough that incidental function-word and stop-word overlap
cannot accumulate, short enough to catch copying that is distributed across a
draft in short fragments rather than one long block. It is a configured rule
parameter, so an Admin can tighten or relax it per rule set.

This narrows the check to what Requirement 6.5 states. Detecting heavy
paraphrase is explicitly **not** in scope for Requirement 6.5 and is not added
here.

### Change 2: the boundary is inclusive, and Requirement 6.5 says so

Standardize on inclusive `>=` and amend Requirement 6.5 to read
`đạt hoặc vượt quá giới hạn` so the requirement matches `tasks.md` and the
implementation.

The alternative — making the code exclusive — would make copying exactly 50
consecutive words compliant. For a copyright control, the inclusive reading is
the safe one, so the document is corrected rather than the behavior.

### Change 3: property numbering becomes traceable, not renumbered

Keep both numbering schemes and add a mapping table to `design.md` that relates
each aggregate design property to the `tasks.md` properties that verify it.
State that test tags use the `tasks.md` numbering. Renumbering either document
would invalidate 35 existing test tags or rewrite the design narrative for no
behavioral gain.

### Change 4: research records permission refusals

Add `skippedSources` to `ResearchResult`, holding the source reference, the
refusal reason, and the effective terms version for every related source skipped
because access was not permitted. Keep it distinct from `unreachableSources`, so
"we were not allowed to read this" is never conflated with "this failed".

## Acceptance criteria

1. A draft sharing only isolated common words with a capture has
   `matchedDraftRatio` below the threshold and `copyrightOk === true`, with no
   stop-word list required.
2. A draft containing copied fragments whose runs each reach `minRunTokens`
   still trips the ratio threshold once the total reaches 20%.
3. Exactly 50 consecutive copied words is still flagged; 49 is not. Exactly 20%
   qualifying matched words is still flagged; 19% is not.
4. `CopyrightComparison` records `minRunTokens` and the qualifying runs, and the
   persisted `ComplianceResult` round-trips them.
5. Requirement 6.5 wording states the inclusive boundary.
6. `design.md` contains a design-property to task-property mapping table, and
   states that test tags follow the `tasks.md` numbering.
7. `ResearchResult.skippedSources` names every permission-refused related
   source with a reason; `unreachableSources` continues to hold only failures
   and timeouts. An origin source that is refused still yields
   `InsufficientData`.
8. Property 23 is updated to assert the corrected semantics and continues to
   cover the 49/50 word and 19/20/21 percent boundaries. Properties 11–13 cover
   `skippedSources`. No property is weakened to match the implementation.
9. `npm test`, `npm run typecheck`, and `npm run build` pass, and `npm audit`
   reports no vulnerabilities.

## Impact

Change 1 is a deliberate, user-visible narrowing of the copyright check: drafts
that were previously flagged solely through incidental vocabulary overlap will
now pass. That removes a false-positive class, and it does reduce sensitivity —
copying spread across runs shorter than `minRunTokens` no longer contributes to
the ratio. The 50-consecutive-word rule is unchanged, and `minRunTokens` is
configurable per rule set, so the trade-off is adjustable without another code
change.

Changes 2 and 3 are documentation only. Change 4 is additive and does not alter
any transition.

Requirement 6.5's wording and the compliance behavior both change, so this
request needs explicit approval before the implementation is merged.
